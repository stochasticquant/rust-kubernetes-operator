# Governance

Ferrogate is an open-source project in its early stage. This document describes how decisions are
made today and how that will change as the community grows.

## Roles

**Users** run Ferrogate and give feedback through issues and discussions.

**Contributors** submit issues, documentation, policies or code. Anyone can be a contributor.

**Maintainers** review and merge pull requests, triage issues, handle security reports, and make
releases. They are listed in [MAINTAINERS.md](MAINTAINERS.md).

## Decisions

- Day-to-day changes are decided in pull requests. A maintainer approves and merges.
- Significant technical decisions (new CRD versions, architecture, security model, dependencies with
  large impact) are written up as a decision record in [`docs/decisions/`](docs/decisions/) and
  discussed in a pull request before they are accepted.
- Maintainers aim for consensus. If there is none, the maintainers decide by simple majority.

## Becoming a maintainer

A contributor who has made sustained, high-quality contributions (code, reviews, docs or support) over
several months can be nominated by an existing maintainer. Nomination is accepted when a majority of
maintainers agree. Maintainers who are inactive for six months may move to emeritus status.

## Security

Security reports follow [SECURITY.md](SECURITY.md) and are handled privately by the maintainers.

## Code of conduct

Everyone in the project follows the [Code of Conduct](CODE_OF_CONDUCT.md). Maintainers enforce it.

## Changes to this document

Changes to governance are made by pull request and need approval from a majority of maintainers.
